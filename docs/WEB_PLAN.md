# 웹판 계획 — 함께 읽는 성경

> 2026-11-24 사용자와 합의 중. 아직 코드 없음. 이 문서를 고쳐 가며 정한다.

## 목적
두 사람(나 · 서버 주인)이 **성경을 읽고, 느낀 점을 적고, 서로 나누는 비공개 공간.**
데스크톱판(설교 준비 · 클립보드 변환 · 자막 발표)과 목적이 다르다. 그래서 성경 엔진과 화면(`web/`)은
같이 쓰되, 웹에서는 **기능 구성이 다르다**(아래 "기능 구성").

## 합의한 것
- 사용자는 **2명**. 회원가입 없음. 서버 설정 파일에 계정 2개.
- **비공개**. 로그인하지 않으면 성경 본문을 포함해 아무것도 보이지 않는다.
- 저작권 역본(개역개정 등)은 **git에 올리지 않는다.** 서버 주인이 서버의 `data/` 폴더에 직접 넣는다.
  git에는 지금처럼 코드 + 개역한글 · 원어 자료만 있다.
- 노트는 **나만 보기 / 함께 보기** 두 갈래.
- 배포: 서버가 **GitHub 저장소**(`tpwns432-maker/BibleClip`, 공개)에서 `git clone` → Docker로 실행.

## 구조
```
[데스크톱]  화면(web/) ←pywebview→  Python(Api)          한 PC 안 (그대로)
[안드로이드] 화면(web/) ←Bridge.kt→  Kotlin               한 폰 안 (그대로)
[웹]       화면(web/) ←HTTPS→     서버 Python(Api)       브라우저 ↔ 서버 (새로)
```
- **서버**: 지금 `bibleclip/webui/api.py`의 `Api`를 그대로 쓴다. 웹 서버는 `/api/<기능이름>` 하나로
  받아 허용 목록에 있는 기능만 부른다. 후보: Flask + waitress(순수 Python, 지금 코드가 동기식이라 잘 맞음).
- **브라우저**: `web/js/bridge-web.js`(새)가 `window.pywebview.api.xxx()`를 `fetch`로 바꿔 준다.
  pywebview도 결과를 Promise로 돌려주므로 화면 코드는 그대로 돈다. `pywebview.platform = "web"`.
- **사람별 데이터**: 성경 엔진(역본 · 검색 색인 · 원어)은 서버에 **한 벌**. 설정 · 형광펜 · 나만 노트는
  `userdata/<아이디>/`에 사람마다 따로. → 1단계에서 `Library`를 "엔진"과 "사람 저장소"로 나눌 수 있는지 확인.

## 기능 구성 (웹)
| 구분 | 기능 |
|---|---|
| 그대로 | 성경 읽기 · 병렬 보기 · 검색(정렬 · 필터) · 원어 사전 · 형광펜(사람별) · 테마 · 설정(사람별) |
| 바꿈 | 원어 사전 창 → 화면 안 창(모달) 또는 새 탭 |
| 숨김 | 클립보드 감시 · 장바구니 · 자막(발표) 창 · F11 발표 · 성경 파일 추가 · 업데이트 확인 · 킬스위치 |
| 새로 | **함께 노트**, **함께 모아보기**, 상대 글이 있는 절 표시, 로그인 화면 |

## 함께 노트
- **나만 노트**: 지금 노트 그대로(절마다 하나, 사람별 폴더).
- **함께 노트**: 서버 공용 저장소(`userdata/_shared/notes.json`). 한 글 =
  `{id, author, book, chapter, verse, text, ts, edited}`.
  - 한 절에 두 사람이 각자, 여러 번 쓸 수 있다. 같은 절의 글이 시간순으로 쌓이면 대화처럼 읽힌다.
  - 고치기 · 지우기는 쓴 사람만.
  - 노트를 쓸 때 **나만 / 함께**를 고른다. 나만 노트를 나중에 함께로 옮길 수 있다.
- **본문 표시**: 함께 글이 있는 절에 표시(나만 노트와 다른 모양). 누르면 그 절의 글이 시간순으로 나온다.
- **함께 모아보기**: 최근 글 흐름(누가 · 어느 구절에 · 무엇을). 누르면 그 구절로 간다.
- **새 글 알림**: 접속하거나 새로고침할 때 "새 글 N개" 정도. 실시간 · 푸시 알림은 하지 않는다.
- 동시에 쓰는 사람이 둘뿐이라 JSON 파일 + 잠금 + 안전한 저장(임시 파일 → 바꿔치기)으로 충분하다.

## 계정 · 보안
- 계정 파일 `config/users.json`(**git 밖**, 서버에만): 아이디 · 보이는 이름 · 비밀번호 해시.
  비밀번호 원문은 어디에도 저장하지 않는다. 설치할 때 명령 하나로 만든다.
- 로그인하면 쿠키로 기억한다(세션). 로그인 실패를 여러 번 하면 잠시 막는다.
- **HTTPS 필수**(비밀번호가 오가므로). 보통 서버에 있는 웹서버(nginx 등)가 맡는다.
- 저장소가 공개라 **비밀 값은 코드에 넣지 않는다**(계정 · 세션 키는 서버 파일 또는 환경 변수).

## 배포
- `Dockerfile` + `docker-compose.yml`. 서버 주인이 하는 일:
  ```
  git clone https://github.com/tpwns432-maker/BibleClip.git
  (역본 파일을 data/에 넣고, 계정 만들기 명령 실행)
  docker compose up -d
  # 업데이트
  git pull && docker compose up -d --build
  ```
- 컨테이너 밖에 두는 폴더: `data/`(역본) · `userdata/`(두 사람의 글 — **백업 대상**) · `config/`(계정).
- 설치 안내서 `docs/WEB_SETUP.md`(서버 주인용).

## 서버 주인께 확인 중
- 운영체제(리눅스?) · Docker 설치 여부
- 도메인 주소 · 이미 돌고 있는 웹서버(nginx 등) · HTTPS 인증서

## 단계
1. **내 PC 브라우저에서 열기** — 웹 서버 + `bridge-web.js`, 한 사람용. 데스크톱 기능 숨김.
2. **로그인 + 사람별 데이터** — 계정 2개, 엔진 한 벌 · 저장소 사람별.
3. **함께 노트** — 저장소 · 본문 표시 · 모아보기.
4. **포장** — Docker · 설치 안내서.
5. **서버 설치** — 서버 주인과 함께.

## 데스크톱 · 폰과의 관계
- 같은 저장소, 같은 `web/` 화면. 웹 전용 동작은 `IS_WEB` 분기로만 넣고 데스크톱 · 폰 동작은 바꾸지 않는다.
  기존 테스트는 모두 그대로 통과해야 한다.
- 데스크톱 노트 ↔ 웹 노트 동기화는 1차에서 하지 않는다.

## 배포 전에 정리할 것
- 공개 저장소 **히스토리에 예전 저작권 파일 6개가 남아 있다.** 서버가 `git clone` 하면 함께 받아간다.
  5단계 전에 히스토리 정리(강제 push — 사용자 승인 후)를 한다.
