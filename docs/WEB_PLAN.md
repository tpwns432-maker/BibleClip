# 웹판 계획 — 함께 읽는 성경

> 2026-11-24 사용자와 합의(답글 · 구절 범위 · 형광펜 공유 · 리눅스·Docker·도메인 없음 반영). 아직 코드 없음.

## 목적
두 사람(나 · 서버 주인)이 **성경을 읽고, 느낀 점을 적고, 서로 나누는 비공개 공간.**
데스크톱판(설교 준비 · 클립보드 변환 · 자막 발표)과 목적이 다르다. 그래서 성경 엔진과 화면(`web/`)은
같이 쓰되, 웹에서는 **기능 구성이 다르다**(아래 "기능 구성").

## 합의한 것
- 사용자는 **2명**. 회원가입 없음. 서버 설정 파일에 계정 2개.
- **비공개**. 로그인하지 않으면 성경 본문을 포함해 아무것도 보이지 않는다.
- 저작권 역본(개역개정 등)은 **git에 올리지 않는다.** 서버 주인이 서버의 `data/` 폴더에 직접 넣는다.
  git에는 지금처럼 코드 + 개역한글 · 원어 자료만 있다.
- 노트는 **나만 보기 / 함께 보기** 두 갈래. 함께 노트는 **구절 범위**에 쓰고 **답글**을 단다.
- **형광펜은 서로 보인다.**
- 배포: 서버가 **GitHub 저장소**(`tpwns432-maker/BibleClip`, 공개)에서 `git clone` 해서 실행.
  서버 = 리눅스, Docker 없음, 도메인 없음(아래 "배포" · "접속").

## 구조
```
[데스크톱]  화면(web/) ←pywebview→  Python(Api)          한 PC 안 (그대로)
[안드로이드] 화면(web/) ←Bridge.kt→  Kotlin               한 폰 안 (그대로)
[웹]       화면(web/) ←HTTPS→     서버 Python(Api)       브라우저 ↔ 서버 (새로)
```
- **서버**: 지금 `bibleclip/webui/api.py`의 `Api`를 그대로 쓴다. 웹 서버는 `/api/<기능이름>` 하나로
  받아 허용 목록에 있는 기능만 부른다. 후보: Flask + waitress(순수 Python, 지금 코드가 동기식이라 잘 맞음).
- **브라우저**: `web/js/bridge-web.js`(새)가 `window.pywebview.api.xxx()`를 `fetch`로 바꿔 준다.
  pywebview도 결과를 Promise로 돌려주므로 화면 코드는 그대로 돈다. `pywebview.platform = "web"`.
- **사람별 데이터**: 성경 엔진(역본 · 검색 색인 · 원어)은 서버에 **한 벌**. 설정 · 형광펜 · 나만 노트는
  `userdata/<아이디>/`에 사람마다 따로. → 1단계에서 `Library`를 "엔진"과 "사람 저장소"로 나눌 수 있는지 확인.

## 기능 구성 (웹)
| 구분 | 기능 |
|---|---|
| 그대로 | 성경 읽기 · 병렬 보기 · 검색(정렬 · 필터) · 원어 사전 · 테마 · 설정(사람별) |
| 바꿈 | 원어 사전 창 → 화면 안 창(모달) 또는 새 탭 · 형광펜 → 상대 것도 보임 |
| 숨김 | 클립보드 감시 · 장바구니 · 자막(발표) 창 · F11 발표 · 성경 파일 추가 · 업데이트 확인 · 킬스위치 |
| 새로 | **함께 노트(구절 범위 · 답글)**, **함께 모아보기**, 상대 글이 있는 절 표시, 로그인 화면 |

## 함께 노트
- **나만 노트**: 지금 노트 그대로(절마다 하나, 사람별 폴더).
- **함께 노트**: 서버 공용 저장소(`userdata/_shared/notes.json`). 한 글 =
  `{id, author, book, chapter, verse, verse_end, parent, text, ts, edited}`.
  - **구절 범위**: `verse`~`verse_end`(예: 요 3:16-18). 1차는 **한 장 안**의 범위만. 장을 넘는 범위
    (예: 롬 7:24-8:2)는 필요해지면 `chapter_end`를 더한다.
  - 범위를 고르는 법: 본문에서 첫 절과 끝 절을 차례로 누르거나, 지금처럼 절을 드래그해 고른 뒤 "함께 쓰기".
  - **답글**: `parent`에 원글 `id`. 답글은 한 단계만(답글의 답글은 같은 줄에 이어 붙음). 답글은 범위를 갖지 않는다.
  - 고치기 · 지우기는 쓴 사람만. 답글이 달린 원글을 지우면 "지운 글입니다"만 남기고 답글은 유지.
  - 노트를 쓸 때 **나만 / 함께**를 고른다. 나만 노트를 나중에 함께로 옮길 수 있다(한 절짜리 글이 됨).
- **본문 표시**: 함께 글이 걸린 절에 표시(나만 노트와 다른 모양). 범위 글은 범위 전체에 옅은 세로줄.
  누르면 그 절에 걸린 글과 답글이 시간순으로 나온다.
- **함께 모아보기**: 최근 글 · 답글 흐름(누가 · 어느 구절에 · 무엇을). 누르면 그 구절로 간다.
- **새 글 알림**: 접속하거나 새로고침할 때 "새 글 N개" 정도. 실시간 · 푸시 알림은 하지 않는다.
- 동시에 쓰는 사람이 둘뿐이라 JSON 파일 + 잠금 + 안전한 저장(임시 파일 → 바꿔치기)으로 충분하다.

## 함께 보는 형광펜
- 저장은 지금처럼 **사람별**(`userdata/<아이디>/user_highlights.json`). 칠하고 지우는 건 자기 것만.
- 보여 줄 때 두 사람 것을 합친다. 내 형광펜은 지금 모양(배경색), **상대 형광펜은 밑줄**(그 사람의 색).
  두 사람이 같은 곳을 칠해도 둘 다 보인다. 상대 형광펜에 손을 대면 누가 칠했는지 나온다.
- 설정에 "상대 형광펜 보기" 켜고 끄기.
- 지금 그리는 코드는 한 사람 것(겹치지 않는 범위)만 가정한다 → 두 겹을 그리도록 고친다(3단계).

## 계정 · 보안
- 계정 파일 `config/users.json`(**git 밖**, 서버에만): 아이디 · 보이는 이름 · 비밀번호 해시.
  비밀번호 원문은 어디에도 저장하지 않는다. 설치할 때 명령 하나로 만든다.
- 로그인하면 쿠키로 기억한다(세션). 로그인 실패를 여러 번 하면 잠시 막는다.
- **암호화된 연결 필수**(비밀번호가 오가므로). 도메인이 없으니 아래 "접속"의 방법으로 해결한다.
- 저장소가 공개라 **비밀 값은 코드에 넣지 않는다**(계정 · 세션 키는 서버 파일 또는 환경 변수).

## 배포 (리눅스, Docker 없이)
Docker는 깔려 있지 않다. 두 명이 쓰는 작은 앱이라 Docker 없이 **Python 가상환경 + systemd**로 간다
(systemd = 리눅스가 프로그램을 켜 두고, 꺼지면 다시 켜고, 재부팅 때 자동으로 켜 주는 장치).
설치 스크립트 `deploy/install.sh`가 아래를 대신 한다. 서버 주인이 하는 일:
```
git clone https://github.com/tpwns432-maker/BibleClip.git
cd BibleClip && sudo deploy/install.sh        # 가상환경 · 서비스 등록 · 계정 2개 만들기
(역본 파일을 data/에 넣기)
# 업데이트
git pull && sudo systemctl restart bibleclip-web
```
- 앱 폴더 밖에 두는 것: `data/`(역본) · `userdata/`(두 사람의 글 — **백업 대상**) · `config/`(계정).
- 설치 안내서 `docs/WEB_SETUP.md`(서버 주인용, 명령을 그대로 따라 치면 되게).

## 접속 (도메인 없음)
도메인이 없으면 일반 https 주소(자물쇠)를 받기 어렵다. 후보:

| 방법 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| **Tailscale**(권장) | 서버와 두 사람 기기에 Tailscale 앱 설치 → 셋만의 사설망. 주소 예: `https://bibleclip.xxx.ts.net` | 인터넷에 아예 안 열림(가장 안전) · 도메인 · 포트 열기 불필요 · https 자동 · 무료 | 접속할 기기(PC · 폰)마다 앱 설치 · 로그인 |
| 무료 주소 + 자동 인증서 | DuckDNS 같은 무료 하위 주소 + Caddy(인증서 자동) | 아무 브라우저로 바로 접속 | 서버를 인터넷에 열어야 함(공유기 포트 열기 · 공인 IP 필요) · 무차별 로그인 시도에 노출 |
| 도메인 사기 | 연 1~2만 원 + Caddy | 깔끔한 주소 | 비용 · 나머지는 위와 같음 |

두 명만 쓰는 비공개 공간이라 **Tailscale**을 권한다. 앱(로그인 화면)은 어느 방법이든 똑같이 둔다.

## 서버 주인께 확인할 것
- 확인됨: 리눅스 · Docker 없음 · 도메인 없음
- 남은 것: 리눅스 종류와 버전(`cat /etc/os-release`) · `sudo` 가능 여부 ·
  서버가 집에 있는지 클라우드(VPS)인지 · Tailscale 설치에 동의하는지

## 단계
1. **내 PC 브라우저에서 열기** — 웹 서버 + `bridge-web.js`, 한 사람용. 데스크톱 기능 숨김.
2. **로그인 + 사람별 데이터** — 계정 2개, 엔진 한 벌 · 저장소 사람별.
3. **함께 노트 · 형광펜** — 구절 범위 · 답글 · 본문 표시 · 모아보기 · 상대 형광펜.
4. **포장** — 설치 스크립트 · systemd · 설치 안내서 · 접속 방법.
5. **서버 설치** — 서버 주인과 함께.

## 데스크톱 · 폰과의 관계
- 같은 저장소, 같은 `web/` 화면. 웹 전용 동작은 `IS_WEB` 분기로만 넣고 데스크톱 · 폰 동작은 바꾸지 않는다.
  기존 테스트는 모두 그대로 통과해야 한다.
- 데스크톱 노트 ↔ 웹 노트 동기화는 1차에서 하지 않는다.

## 배포 전에 정리할 것
- 공개 저장소 **히스토리에 예전 저작권 파일 6개가 남아 있다.** 서버가 `git clone` 하면 함께 받아간다.
  5단계 전에 히스토리 정리(강제 push — 사용자 승인 후)를 한다.
