## 구조
```
[서버] BibleClip 웹 서비스 ── 같은 프로그램 안의 봇 스레드 ──(밖으로만)──▶ api.telegram.org
```
- **새 서비스 · 새 라이브러리 없음**: 웹 서비스 안에서 도는 작은 스레드 하나. 표준 라이브러리(urllib)로 텔레그램에 묻는다.
  → 설치는 지금처럼 `update.sh` 한 번. 서버 주인이 따로 설치할 것 없음.
- **폴링**(봇이 텔레그램에 "나한테 온 메시지 있어?"를 묻는 방식): 집 서버에 들어오는 문을 새로 열지 않는다.
- **봇 열쇠(토큰)**: 세준 님이 `@BotFather`에서 봇을 만들고 받은 토큰을 **사이트에서 한 번 입력** →
  서버 데이터 폴더(`telegram.json`, 권한 600)에만 저장. GitHub · 설정 파일에는 없다. 서버 주인 손을 거치지 않는다.
- **시간대**: 서버 시계는 UTC 일 수 있다(서버 기록 시각이 한국과 9시간 차이). 알림 시각은 항상 **Asia/Seoul** 로 계산.

## 연결(각자 한 번)
1. 사이트 홈 아래 **"텔레그램 연결"** → 10분짜리 연결 링크(`https://t.me/<봇>?start=<일회용 코드>`)가 뜬다.
2. 폰에서 링크를 열고 **시작**을 누르면 봇이 그 텔레그램 대화를 그 BibleClip 계정에 묶는다.
3. 연결된 뒤 홈에서 켜고 끄기: 커뮤니티 알림 · 통독 알림. **"연결 끊기"**, 봇에 `/stop` 도 같은 효과.
- 연결되지 않은 대화에서 온 메시지에는 "사이트에서 연결해 주세요"만 답한다(아무 정보도 주지 않음).

## 커뮤니티 알림
- 상대가 새 글을 쓰면: `📖 BibleClip · 커뮤니티에 새 글이 있어요` + 그 글 링크.
- 상대가 댓글을 달면: `💬 BibleClip · 새 댓글이 있어요` + 그 글 링크.
- 짧은 시간에 여러 개면 묶는다(2분 안의 것은 한 번에 "새 글 1 · 새 댓글 3").
- 내가 쓴 것은 나에게 알리지 않는다.

## 통독 알림
- 계획: **1년 1독**(66권 1189장 → 하루 약 3.3장, 성경 순서). 두 분이 **같은 계획 · 같은 날짜**로 읽는다
  (커뮤니티 '성경 묵상'에서 같은 본문을 나누기 좋게).
- 아침 8시: `☀️ 오늘의 통독 (12일째) · 창 34–36장` + 성경 화면 링크(그 첫 장으로 열림).
- 저녁 7시: `🌙 오늘의 통독 다 읽으셨나요? · 창 34–36장` + 링크.
- 하루의 범위는 장 수를 고르게 나눈다(예: 3장 · 4장이 섞임). 365일이 지나면 처음부터 다시.
- 서버가 꺼져 있다 다시 켜져도 지난 알림을 몰아서 보내지 않는다(놓친 것은 건너뜀).
